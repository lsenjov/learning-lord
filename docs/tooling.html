Tooling

The repository contains a Rust 2024 workspace, a setup-only native binary, and a minimal Rust/WebAssembly browser scaffold.

Rust in a new shell

Rustup is installed on this machine under ~/.cargo/bin. Load its environment in any shell that cannot find Cargo:

. "$HOME/.cargo/env"

The repository pins Rust 1.98.1 in rust-toolchain.toml, including rustfmt, Clippy, rust-analyzer, and the wasm32-unknown-unknown target.

On another machine, first follow the official rustup installation instructions. Running Cargo inside this repository installs the pinned toolchain and its listed components when missing. Native compilation also needs a system linker; this machine's existing linker was sufficient.

Project commands

Run these from the repository root:

cargo fmt --all -- --check
cargo clippy --workspace --all-targets -- -D warnings
cargo test --workspace
cargo run -p learning-lord
cargo build --workspace
trunk build
trunk serve

trunk build packages the browser crate into the ignored crates/browser/dist directory. trunk serve watches the browser files, rebuilds after changes, reloads the page, and serves it at http://127.0.0.1:8080. Stop it with Ctrl+C.

This reloads the whole page after a successful build; it does not preserve application state. If Trunk rejects an existing NO_COLOR=1 environment setting, run NO_COLOR=true trunk serve (or NO_COLOR=true trunk build).

The starter prints Learning Lord tooling is ready. and has zero tests. Add behavioral tests as you implement the lessons. To apply formatting rather than check it, run cargo fmt --all.

The browser page starts as Loading…; Rust replaces it with Hello world after the WebAssembly module loads. During trunk serve, build failures appear on the page and in the browser console; load or runtime failures appear in the console.

This machine uses a prebuilt Trunk release. On another machine, follow the official Trunk installation guide; it documents prebuilt releases and cargo install --locked trunk. Trunk builds the wasm32-unknown-unknown target listed in rust-toolchain.toml, packages the wasm-bindgen loader, and provides the local development server.

Optional Neovim setup

The project configuration needs Neovim 0.11 or later (verified with 0.12.4) and uses its built-in LSP client with rust-analyzer. It loads independently of personal Neovim configuration and installs no plugins. Load the Cargo environment first, then run from the repository root:

nvim -u tools/nvim.lua crates/learning-lord/src/main.rs

Run :checkhealth vim.lsp in Neovim to inspect the attached language server.

  • Hover: :lua vim.lsp.buf.hover()
  • Go to definition: :lua vim.lsp.buf.definition()
  • Show diagnostics: :lua vim.diagnostic.open_float()
  • Format the buffer: :lua vim.lsp.buf.format()

These are optional commands for the supplied configuration. Your personal configuration may already provide mappings or Rust support; do not enable a second rust-analyzer client there. Reference: Neovim LSP documentation.

Conjure and the Rust REPL

Your personal Neovim configuration includes Conjure, which starts evcxr for Rust buffers. This is a separate REPL executable, supplied by the evcxr_repl Cargo package. If Conjure reports that it cannot find it, run these commands from the repository root after loading the Cargo environment:

rustup component add rust-src
cargo install --locked evcxr_repl

Restart Neovim from that shell. Inside Neovim, :echo exepath('evcxr') should show its installed path. Repeat the source-component command after changing the project's pinned Rust version if the REPL needs it.

The supplied plugin-free Neovim configuration does not use Conjure. Reference: Evcxr installation and usage.

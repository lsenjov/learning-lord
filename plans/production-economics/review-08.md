# Review 08 — future product value

Verdict: agree with deferring. Reject direct product valuation; the bounded terminal benefit is a research proposal with an explicit design gate, not an implementation-ready substitute. The document already identifies most of its risks honestly. The following decisions must resolve that gate before implementation. No builds, simulations or counterfactual replays were run.

## Prioritized findings

1. **High — a sale estimate is not an ending-wealth increment, and the accounting identity remains unspecified.** Ordinary wealth counts held and listed goods at reference (`lib.rs:732`); the evidence distinguishes garment reference value 139.22 from estimated seller value 147.41. Completing an unsold garment must therefore use reference output value; receiving sale proceeds requires a feasible sale assumption, including delay and buyer demand. Otherwise a terminal estimator awards a sale premium that an actual completed-work rollout does not receive. Specify one outcome and one identity: output reference value minus consumed held-input reference value minus actual missing-input expenditure minus incremental fees, for an unsold-output estimate. A sale variant replaces output reference with net realised/explicitly modelled proceeds, never adds both. State that missing-input reference value is not also deducted after purchase expenditure, and that existing fee liabilities are not charged twice. With an owned block worth about 12.50 and seven imports costing 132, the 147.41 sale estimate gives about +2.91 before further costs, while the 139.22 unsold reference estimate gives about -5.28. This distinction can reverse Finn's choice.

2. **High — define the score operation and remaining-work deduction together.** `WeightedWellbeing::add` averages endpoint wellbeing over elapsed action time (`goals.rs:377`), and personal wellbeing converts coins using 0.1 (`lib.rs:1460`). Adding a coin bonus directly to that average mixes units; adding it to only a final action endpoint gives a weight dependent on how the candidate was segmented. Even converting to wellbeing does not settle how a terminal reward compares with duration-averaged needs. A common comparison boundary is necessary, but insufficient without a documented terminal weighting. Specify where the benefit enters both goal and plan selection, its conversion/weight, and whether remaining labour is a monetary opportunity cost or projected needs loss. Do not charge the same future fatigue/needs cost through both simulated continuation and a labour deduction. Conversely, a time discount alone does not pay those costs. For example, buying inputs just before a boundary can receive the uplift while a competing candidate that actually works incurs fatigue and loses the bonus as inputs become output. Test this transition, unequal candidate durations, and repeated replanning with a fixed symbolic example before choosing constants.

3. **Medium — per-workplace feasibility does not imply jointly feasible continuation.** Allocating ingredients once prevents one kind of double counting, but one worker can access several workplaces, and several recipes can compete for the same missing-input listing, money or available time. For example, two proposed batches each requiring 80 coins are individually affordable with 100 coins, but cannot both justify an account's terminal reward. A deterministic greedy order is acceptable for a bounded experiment only if it also reserves cash, listing depth, travel/production time and owned inputs across the entire selected set. Specify the ordering and a finite continuation budget. Prefer one next batch per agent/account for the first diagnostic; it avoids inventing a multi-workplace schedule merely to estimate a bonus.

## Finn impact and simpler alternative

The saved quantities span several garment batches, while the proposed first estimate credits only one next batch. It can therefore leave most bulk procurement's immediate reference loss uncompensated. A negative result would not show that future production has no value; a positive result would not establish that Finn actually completes or sells the work. The day-14 and day-16 saves must remain separate, and no evidence currently establishes an inactivity fix for either.

Keep the document's first step: manually complete one feasible batch on an isolated clone and compare actual cash, goods, needs and elapsed time against the current candidate. Record both the unsold endpoint and any actual sale separately. Then prefer the smaller procurement experiment if it addresses the observed loss, or plan 03's common-period continuation if delayed payback is demonstrated. These avoid introducing a second wealth-like signal whose labour price and terminal weight require calibration.

## Performance and required revisions

Bound the diagnostic by explicit site/recipe enumeration and one chosen batch; avoid recursively asking for the best earning rate to price labour. Reuse a snapshot of input availability, ownership and listing depth across candidates where valid. Measure cold/warm median and p95 decision time and allocation counts under the shared protocol; an account cap limits reward magnitude, not computation.

Before reopening implementation, revise the plan to select the accounting outcome, score integration, labour semantics, joint resource/time budget and deterministic order. Add assertions for the numerical valuation distinction above, equal-state candidates with different action segmentation, work completion versus procrastination, shared cash/listings/workplaces, and garments used for clothing needs. The existing explicit ban on combining the same terminal uplift with realised continuation is sound and should remain. Keep fermentation/growth excluded from the first experiment. This review does not authorize implementation.

## Fresh review of revised diagnostic scope

The revised plan selects one feasible immediate batch per account on independent clones, requires real preparation/production and resource feasibility, excludes recursive chains and delayed crop/fermentation inputs, and reports unsold output at reference. Its accounting now explicitly distinguishes existing-input reference value from missing-input cash expenditure, excludes speculative sale funding, avoids recharging liabilities and reconciles the estimate with the simulated balance-sheet delta. This addresses findings 1 and 3 within the diagnostic's scope. The diagnostic can measure an economic delta and elapsed work; it cannot establish that adding that delta to the current scoring system is correct.
